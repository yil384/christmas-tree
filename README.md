# 一棵送给你的圣诞树

一份可以直接在手机浏览器里打开的圣诞礼物：点亮星光、转动树身、翻看照片，再读一封冬日来信。

新版保留 React、TypeScript 和 Vite，使用 Canvas 2D 绘制具有空间感的粒子圣诞树。收礼人通过触摸和按钮操作；页面不需要摄像头，也不下载手势识别模型。照片先生成轻量缩略图，查看时再加载较大的显示图。

**目前仓库里的照片是旧版保留下来的临时内容，尚未替换为这次礼物的最终照片。** 可以先完成页面，再决定放多少张；照片数量不需要写进代码。

## 本地运行

准备 Node.js 和 npm。开发环境已在 Node.js 24 上运行；安装依赖后使用以下命令：

```sh
npm install
npm run dev
```

`npm run dev` 会先处理照片，然后启动 Vite。打开终端显示的本地地址。

```sh
npm run build
npm run preview
```

`npm run build` 会依次处理照片、检查 TypeScript、生成页面，并移除构建产物中的原始照片。最终可部署内容位于 `dist/`。`npm run preview` 用于本地检查这个正式构建，不会自动发布到互联网。

```sh
npm test
```

测试覆盖照片清单、排序、图片处理、空相册、原图保护，以及构建产物的清理边界。

## 换照片：不需要决定固定数量

1. 将想使用的图片放进 `public/photos/`。不再使用的旧图片应移出这个目录，或用下面的清单明确选择要展示的图片。
2. 支持 `.jpg`、`.jpeg`、`.png`、`.webp`、`.avif`，扩展名不区分大小写。文件名可以含中文和空格，不必改成连续数字。
3. 重新运行 `npm run dev` 或 `npm run build`。开发服务器已经运行时，增删或替换照片后重新启动它，确保清单和缩略图更新。

默认读取目录中的所有图片，不递归读取子目录，也不跟随符号链接。`top.*` 优先，其余按文件名自然排序，例如 `1.jpg`、`2.jpg`、`10.jpg`。`top.jpg` 现在只是排序靠前的照片，不是树顶五角星的贴图。

没有照片、一张照片或更多照片都可以使用。图片数量增加时，无需修改 React 组件、常量或布局代码。

### 可选：指定顺序和照片文字

创建 `public/photos/manifest.json`：

```json
{
  "photos": [
    "top.jpg",
    {
      "file": "海边 1.jpg",
      "caption": "想留下的那一天",
      "alt": "海边的合照"
    },
    "2.jpg"
  ]
}
```

存在清单时，只展示其中列出的图片，并保留清单顺序。`caption` 是可选的说明文字；`alt` 是辅助阅读文字。条目可以直接写文件名，也可以写包含 `file` 的对象。

- 文件必须实际存在于 `public/photos/`，不接受路径、远程图片地址或重复条目。
- 暂时不放照片时，使用 `{"photos": []}`；之后把照片加入清单即可。
- 删除清单后，恢复自动发现全部照片。
- JSON 需要双引号，最后一个条目后不要加逗号。

### 图片如何优化

构建前的 `scripts/prepare-photos.mjs` 会自动完成以下工作：

| 内容 | 处理方式 |
| --- | --- |
| 缩略图 | 最长边不超过 320 px，WebP，质量参数 75 |
| 点击查看的图片 | 最长边不超过 1600 px，WebP，质量参数 82 |
| 小尺寸原图 | 保持尺寸，不放大 |
| 手机拍摄方向 | 按 EXIF 方向旋转到正确方向 |
| 图片元数据 | 输出中去除 EXIF 等元数据 |
| 文件名 | 使用哈希生成资源名，适用于中文或带空格的源文件 |
| 大型或损坏的文件 | 报出具体文件名；单张超过 6400 万像素时要求先缩小 |

处理过程逐张执行，原图不会被改写。生成文件写入 `public/generated/photos/`，清单写入 `public/generated/photo-manifest.json`。这些内容由构建再生成，不需要提交到 Git。

正式构建会删除 `dist/photos/` 中复制过来的原图，只保留页面使用的生成图片；`public/photos/` 仍保留原始输入。若某张图片损坏，处理会停止并给出错误，先前生成的清单保留。

## 改称呼、祝福和来信

编辑 `public/gift.json`。例如：

```json
{
  "recipient": "送给你",
  "headline": ["把这一年的星光，", "都送给你。"],
  "subtitle": "愿每个平凡的日子，都有一点闪闪发光。",
  "letter": [
    "圣诞快乐。",
    "把想说的话写在这里，每一项是一段。",
    "愿这个冬天，有温暖，也有小小的惊喜。"
  ],
  "signature": "写下你的名字",
  "year": 2026,
  "music": null
}
```

`headline` 是两行标题，`letter` 是段落数组。保持字段类型不变。内容只是示例，发布前替换为你真正想说的话。

`music: null` 时，音乐按钮播放内置的轻柔合成铃声，无需下载音频文件；默认保持静音。需要换成自己的音乐时，将音频放进 `public/music/`，把 `music` 改为类似 `"music/your-track.mp3"` 的相对路径。声音需要收礼人点击开启；不要把自动播放当作已保证的体验。

## 发布和送出

整个项目是静态网站，部署时上传 `dist/` 即可。配置使用相对资源路径，可以部署到现有自定义域名，也可以部署到 GitHub Pages 的 `/christmas-tree/` 子路径。更换托管平台后，检查首页、照片和音乐是否都能正常加载。

现有 `public/CNAME` 保留了 `www.weiyirao.com`。沿用这个域名时保留它；决定切换到免费的 GitHub Pages 地址时，需要同时移除 `public/CNAME` 并清空仓库 GitHub Pages 设置中的自定义域名，随后重新构建、部署。仅修改页面标题或 `package.json` 的 `homepage` 不会完成域名切换。

项目保留了 `gh-pages` 发布命令。确认部署目标和礼物内容后，可在具有仓库推送权限的本地环境运行：

```sh
npm run deploy
```

这会先构建，再把 `dist/` 发布到 `gh-pages` 分支。GitHub Pages 仍需在仓库设置中选定正确的发布来源。普通的本地预览不会修改线上网站。

### 给收礼人的入口

把最终发布的地址发成微信里的短消息，或做成一张可以扫码的实体／电子贺卡。她只需点开链接或扫码，不需要购买、理解或管理域名。

页面里的分享或二维码功能应在**最终部署地址**上使用。不要将 localhost、开发预览地址或临时测试地址制作成正式贺卡。微信的分享封面、链接打开方式和系统分享能力可能随客户端变化；普通网页不能保证出现微信小程序卡片。

网页清单可以提供浏览器支持的桌面快捷方式信息。项目没有 Service Worker，不提供离线访问保证，也不要求收礼人安装应用。

## 发送前检查与后续维护

- 替换临时照片，核对称呼、祝福、签名和年份；构建后检查照片顺序与横竖图显示。
- 在收礼人实际使用的手机和微信中测试点开、触摸、看照片、读来信与音乐。开发浏览器检查不能代替真实微信测试；目前尚未验证具体手机上的微信行为。
- 用对方所在地区的网络打开最终地址，确认首屏和照片的实际速度。资源体积缩小不等于任何地区、任何运营商都能快速访问。
- 保存源文件和 `gift.json`。之后换照片或文字，重新构建并部署即可；域名继续使用时留意其到期时间。

当前 GitHub 仓库是公开的，仓库里的原图和历史提交可以被访问。构建时排除原图只影响部署产物，不能隐藏 Git 历史；照片清单也不是访问控制。如果照片不适合公开，上传前应确认收件人的同意，并考虑有访问控制的私有托管；私有仓库本身不保证网页私密。

## 代码结构

| 路径 | 用途 |
| --- | --- |
| `src/` | React 界面、Canvas 2D 空间投影与交互 |
| `public/gift.json` | 称呼、标题、来信、年份与音乐设置 |
| `public/photos/` | 自己维护的原始照片与可选清单 |
| `public/generated/` | 自动生成的 WebP 图片和运行时照片清单 |
| `scripts/prepare-photos.mjs` | 照片发现、校验与压缩 |
| `scripts/finalize-build.mjs` | 构建完成后排除原始照片和旧模板图标 |
| `tests/` | 照片管线与构建保护测试 |
| `dist/` | 构建完成后的部署目录 |

旧版依赖 Three.js、React Three Fiber、后期光效和 MediaPipe 手势识别；新版收礼页面使用 Canvas 2D 的空间投影表现树的旋转和粒子效果。这个版本不提供原生 WebGL 场景或摄像头 AI 手势控制。
