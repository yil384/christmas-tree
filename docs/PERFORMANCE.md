# 原版照片树的性能优化

基线为 `844295431c728a315494ba59c9601572e7fcf818`。本次纠正先前偏离需求的 Canvas 2D 改版，恢复照片包裹树身的真实 3D 场景。旧改版的截图、86% 包体缩减数字及相关说明已撤掉。

## 保留的视觉结构

原版圆锥高 22、半径 9；树组放在 y=-6。保留桌面 300 张拍立得实例、大小层级、七种柔和彩色边框、双面照片、绿色树叶、彩灯、立体金星，以及完整照片层的散开／聚合。窄屏仍有 220 张卡片，不用少数固定卡片替代树体。

树上照片、灯与挂件共享旋转父组。雪和背景星点独立于旋转父组。主界面保持全屏，仅留下底部操作。没有自动摄像头、手势识别模型或远程 HDR 环境图。

树用照片的传输体积约减少 94.8%。这来自照片尺寸与格式的调整，不代表页面加载时间按同一比例缩短。大图只在相册需要时加载。

## 渲染与内存改动

### 照片

原版每个拍立得由前后照片与前后边框四个 mesh 构成，300 个实例共约 1,200 个 mesh。现在用一个 InstancedMesh、一个 ShaderMaterial 和一张图集表示整层照片，保留双面可读与点击定位。它在正常场景通道中是一个绘制批次；并非把 300 张照片删成几张。

图集采用 128 px 单元，有内缩 UV 和扩边，无 mipmap，避免相邻图片串色。当前 32 张照片使用 1024×1024 RGBA 图集，像素内存 4 MiB；最大 2048×2048，为 16 MiB，不随大量原始照片无限增长。图片解码和 WebGL 渲染目标等另占内存，这个数字不是整个页面的内存占用。

最多三张缩略图并行加载；树与边框无需等所有照片。单张失败保留占位，继续后续队列。照片归位后停止逐帧更新各卡片的矩阵，转动只更新父组。

### 树叶、灯和挂件

绿色树叶用一个点对象；400 盏彩灯合并为一个点对象。200 个挂件分为三批几何实例；顶星单独一批。雪与背景星点各一批。包含照片，场景本身共九批对象；后期 Bloom 有额外全屏绘制，实际总 draw calls 必须通过 WebGL 实测，不能用九批对象替代实测结果。

桌面保留 15,000 个树叶点。窄屏降为 9,000 点，使用较低后期分辨率。辉光阈值高于普通照片白色，避免把照片边框过度糊亮。图片仍保留完整颜色。

### 生命周期与交互

移除 MediaPipe、摄像头、手势推理循环及远程模型。拖动、缩放、按钮直接控制场景。后台页面与打开弹窗时暂停渲染；系统开启“减少动态效果”时采用按需帧。动画使用时间步长与阻尼，并限制后台恢复后的大时间步。

OrbitControls 在 effect 中连接和断开事件，支持 StrictMode 重挂载。相机默认位置经过卡片四角投影检查，窄屏按宽度拟合；用户仍可主动放大与转动。照片朝向使用固定向上轴，修正原版 lookAt 局部／世界坐标混用以及背侧方向翻转的问题。

## 验证及未完成的部分

已检查构建、ESLint、照片生成与部署保护测试，以及卡片布局的圆锥覆盖、朝向、大小层级、有限矩阵和散开边界。相册、翻页、分享二维码的页面操作也可单独验证。

当前测试浏览器返回 `Could not create a WebGL context / GL_VENDOR=Disabled`；原版也在同一浏览器失败。这个环境不能给出实际 GPU 渲染截图、shader 编译成功或帧率结果。

因此本次仍保留原站，并发布独立修正预览。真实 3D 观感、不同手机 GPU 的帧率、微信内置浏览器兼容性属于尚待真实设备验收的部分。未声明“所有视觉测试通过”，也未用被撤回的 Canvas 2D 截图为本次效果背书。
