| 首屏 JavaScript gzip | 355,158 B | 56,846 B |
| CSS | 911 B | 19,428 B |

首屏 JavaScript 原始体积约减少 **86.5%**，gzip 体积约减少 **84.0%**。首屏还读取一个小型礼物配置和照片清单，不等待照片或音频。

## 照片

现有 32 张照片只作为待替换的预览素材，没有添加或推定最终礼物照片。

| 资源 | 实测字节数 |
| --- | ---: |
| 原始 JPG 合计 | 5,988,722 B |
| 32 张 WebP 缩略图合计 | 311,472 B |
| 点亮后展示的前 5 张缩略图 | 54,196 B |
| 32 张展示尺寸 WebP 合计 | 4,105,400 B |

点亮前不挂载照片 `<img>`；点亮后只展示最多 5 张缩略图。打开相册时只加载当前一张较大图，每页至多挂载 18 张带 `loading="lazy"` 的缩略图。图库不会为了显示一棵树等待整套大图。展示图保留比例、自动旋正、限制最长边 1600 像素，缩略图最长边 320 像素，均不放大小图并去除 EXIF 元信息。原图仍保存在源码目录；正式 `dist/` 不再包含原图副本。

## 原版瓶颈

- 32 张原图通过 `useTexture` 一次加载；同一 Suspense 内还有彩灯、装饰和顶星，一张慢图会拖延整组显示。
- 300 个重复照片相框各有 4 个网格，加上 200 个装饰和 400 个彩灯，仅这三类就有 1,800 个独立 Mesh。这个数来自源码，不是实测 draw calls；15,000 个树叶点实际是合批绘制。
- 初始页面自动加载 MediaPipe、远程 WASM、Google 托管模型及 HDR 环境资源。切换 Debug 会重新初始化识别器，旧摄像头轨道和识别器未完整释放。
- 全尺寸照片按原始尺寸计算的 RGBA8 存储量约为 295 MiB；这是像素量推算，不是实测显存。

## 新版取舍

使用 Canvas 2D 对空间粒子进行透视投影，保留树的深度、旋转、发光、飘雪和散开效果。它不再使用原生 WebGL 场景，也不再包含摄像头手势识别。绘制无需远程模型、HDR、字体、音乐或渲染库。

- 小屏/大屏分别使用 1,550 / 2,250 个树叶粒子；按颜色与前后层分组绘制。
- 小画布/大画布目标更新上限为 30 / 45 FPS；这只是代码设定的目标，不能保证设备实测帧率。
- DPR 上限分别为 1.35 / 1.6。
- 页面隐藏、树移出视口、手动暂停、系统减少动态效果设置都会停止持续动画。
- 默认音乐只在点按时通过 Web Audio 合成，后台停止并释放资源；可配置自己的音频。
- 相册与二维码按需加载；可选面板下载失败时有局部错误恢复，不影响树和关闭按钮。
- 相对路径支持自定义域名、GitHub 项目子路径与预览子目录。

## 已验证与限制

- TypeScript 与 Vite 生产构建通过。
- 9 项 Node 测试通过，涵盖排序、任意照片数、清单验证、真实图片转码、EXIF 旋正/去元信息、坏图保护、构建清理边界。
- 浏览器检查了桌面、390 px 与 320 px 宽度。320 px iframe 内实际内容宽度 305 px，页面 `scrollWidth` 与 `clientWidth` 均为 305，没有横向溢出。
- 已操作点亮、散开/聚合、照片切换、Escape 关闭、来信、二维码、复制链接与音乐开关。
- 浏览器扩展自身日志与应用日志分开判断；未观察到新版应用报错。
- 尚未在收礼人的实际手机、微信 WebView 或中国大陆移动网络做测速；不把包体缩减换算成虚构的秒数或 FPS。
- 添加到主屏幕只提供入口便利；没有 Service Worker，不承诺离线可用。微信分享卡片外观需真实微信验证。
